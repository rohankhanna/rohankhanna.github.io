posture

posture assesses a device's security posture and marks what it could not assess.

Repository on GitHub

The problem

Every vulnerability scanner answers the same narrow question: which known Common Vulnerabilities and Exposures match this machine? That is a real question, and it is one dimension out of six. The other five are the ones that actually decide whether a device is in trouble: how it is configured, what is reachable from the network, what is installed, what is being exploited in the wild right now, and whether what is installed can be trusted at all.

The crowded ground is defect matching, and posture does not compete there. Grype and Trivy are compared against each other constantly (https://devsecops.ae/trivy-vs-grype), OpenVAS sits in the same vulnerability-scanning field (https://www.cycognito.com/learn/vulnerability-assessment/vulnerability-scanning-tools), and DefectDojo and Prowler are the aggregation and cloud-posture tools that a recent comparison of the open-source tools lists side by side (https://defectdojo.com/blog/top-11-open-source-vulnerability-management-tools-for-2026). posture does not match defects and does not try to. It is a verdict engine: it refuses to score an axis it did not examine. None of those tools produces a verdict for an axis it did not examine — they emit findings, so an area they never looked at comes back as silence, and silence reads the same as a clean result.

The uncomfortable part is what happens when a scanner cannot answer. Most tools report zero findings for a dimension they never looked at, and zero findings reads exactly like a clean bill of health. posture takes the opposite position: a dimension with no evidence is a loud UNKNOWN, never a silent "clean".

The project draws this from the map-and-territory distinction. The public catalog of defects, advisories and known-exploited vulnerabilities, drawn by outside authorities, is the map. Your device, with its real installed versions and its real configuration, is the territory. posture assesses the territory using the map and refuses to pretend the map is the territory. A clean result means the map places nothing here, not that the device is invulnerable. Unmapped territory — unreported bugs, software with no Common Platform Enumeration identifier, firmware the National Vulnerability Database never scored — has no coordinates and is reported as UNKNOWN, not as safe.

cares

  • Security engineers who want a provenance-aware picture of a host, with missing evidence surfaced rather than papered over. They gather on Hacker News, on the r/cybersecurity and r/sysadmin subreddits, and in the security engineering Slack and Discord communities.
  • Fleet and portfolio tooling teams that need device-specific assessment to stay local while consuming one shared, signed catalog of public defect data. They gather on Lobsters, on infrastructure mailing lists, and in platform-engineering communities.
  • Downstream tool builders who want the catalog ingestion and the assessment engine as a Python library. They gather on PyPI-adjacent developer blogs, on Dev.to, and in the project issue tracker.

t it does

  • Assesses six dimensions of a host: known defects (vulnerability), misconfiguration (configuration), network reachability (exposure), what is installed (inventory), what is being exploited in the wild (threat), and whether installed artifacts can be trusted (trust).
  • Combines public data — the National Vulnerability Database, MITRE, OSV, the GitHub Advisory Database, the CISA Known Exploited Vulnerabilities list and vendor advisories for Ubuntu, Debian and Apple — with evidence you produce: a Software Bill of Materials, a configuration snapshot, a socket capture, signatures, and vendor package lists.
  • Reports UNKNOWN for any dimension with no evidence, and marks the overall result incomplete while any dimension is unknown.
  • Stamps every verdict with the observer that produced it and the time, stores that provenance, and can mark a source's verdicts as distrusted retroactively without deleting the history of what you once believed.
  • Builds and signs a sharded defect catalog, published as a signed manifest that a consumer can verify by signature and then by shard hash before importing it.
  • Registers nine observers behind one uniform contract — nvd, ubuntu_tracker, debian_tracker, apple_advisory, cyclonedx_sbom, cis_checker, local_exposure, kev and sigverify — so a new source is one module rather than an engine change.
  • Ships a trust policy as versioned, dated YAML, a public-infrastructure event ledger for upstream source reliability, and a command line interface with catalog ingestion, export, import, purge, audit, distrust and health subcommands.

t it does not do

These limits are in the project's own README and they are the credibility asset. They belong in the post.

  • It does not scan your machine. posture is device-agnostic: you represent a device as a small YAML file and point posture at evidence you gather.
  • It does not turn a clean result into a claim of safety. The map is not the territory, and a clean dimension means the map places nothing there.
  • It does not convert missing evidence into a pass. A dimension with no observer is loud UNKNOWN, and the overall result stays incomplete.
  • It does not cover unreported bugs, software with no Common Platform Enumeration identifier, or firmware the National Vulnerability Database never scored. Those have no map coordinates.
  • It is not on the Python Package Index. It is source-installable only, and it is experimental at version 0.1.0, with no API stability guarantee. The programmatic interfaces may change.
  • It does not send device data unless you ask it to. Only the --live path queries the National Vulnerability Database, and it sends the device's software identifier. Offline and catalog assessment send nothing.
  • It does not yet wire the whole catalog into local assessment. Today only the Apple fix-version overlay from the imported catalog flows into a live assessment; the rest is browsable library data.
  • It does not have a working credentialed lane. The commercial-source path is scaffolded in continuous integration but dormant: no credentialed observers are wired and no credentialed-only records exist.
  • It does not promise a stable set of dimensions. Six default axes ship today, and the axes are vocabulary held as data, so the set can change.

tall, in one line

git clone https://github.com/rohankhanna/posture.git && cd posture && python -m pip install -e .

Python 3.11 or newer is required, and the runtime dependencies are installed with the package. git and curl are needed only for network ingestion and live assessment, not for the offline demonstration.

  2. Lobsters — the reader there wants the mechanism, not the outcome: the observer contract, the policy order, the signed catalog, the shard hash verification. A short, technical, low-announcement entry lands better here than a launch post.
  3. r/sysadmin — the reader is an infrastructure operator who has been burned by a scanner reporting zero findings. Lead with the missing-evidence problem and with the fact that posture does not touch the machine, which is the part that makes it usable on an air-gapped or customer-held host.
  4. r/cybersecurity — the reader wants the threat model and the provenance model: who produced each verdict, how a source is distrusted retroactively, and what the trust policy is. The distrust and audit commands are the conversation there.
  5. Dev.to, or a long-form post on your own site — the reader wants the argument in prose: why UNKNOWN is a result and not an error, and why the map-and-territory distinction changes what a fleet view can claim. This is also the surface that keeps working after the day is over.
  6. Curated list and directory surfaces — the awesome lists that collect vulnerability scanners, Software Bill of Materials tooling and supply-chain security tools, and the software directories that index command line tools by language and licence. An entry in a collection that a reader already browses is a permanent recommendation rather than a spike of traffic that decays within a day.

three hardest questions

"A dimension with no observer reports UNKNOWN. That is the same as reporting nothing, with extra steps." No — UNKNOWN is a result, not an absence of one. The demonstration deliberately shows four of six dimensions coming back UNKNOWN while the fifth returns four concrete verdicts, and the overall headline stays incomplete until every dimension has an observer. The point of the tool is that it refuses to convert absence of evidence into evidence of absence, which is precisely what a scanner that reports zero findings does. posture is also not a collector: it assesses the evidence you supply, so what stays unknown is always traceable to a specific input you did not provide.

"Your demonstration shows CVE-2026-99901. Where does the real data come from?" The bundled default is a synthetic fixture, and the README says so plainly. There are two real paths. The --live flag queries the National Vulnerability Database directly and is the only path that sends anything to a third party, in this case the device's software identifier as the virtualMatchString parameter. The other is the signed catalog: continuous integration builds and signs it every six hours, you verify the manifest signature and then the shard hashes, and you import it. The honest caveat, which belongs in the answer, is that only the Apple fix-version overlay from the imported catalog currently reaches a live assessment; the National Vulnerability Database observer has no catalog path yet, and wiring more of it is ongoing work.

"This is a viewer for data other people collected. Where is the engineering?" The engineering is in the parts that are not the data: the uniform observer contract that makes a new source one module; the policy order in which a vendor observer overrides the National Vulnerability Database on the same Common Vulnerabilities and Exposures identifier; the provenance record on every verdict and the retroactive distrust that marks rather than deletes; the atomic publish path that guarantees a served catalog is the last verified snapshot or the new one and never a mixture; the bounded-growth purge that refuses to forget a known-exploited defect; and the command gate that fails loudly when the deployment script calls a command the package no longer ships.
